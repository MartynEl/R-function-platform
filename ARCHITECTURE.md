# Архитектура гибридной рекомендательной системы (FM + R-Functions)

Платформа представляет собой высокопроизводительный двухэтапный конвейер ранжирования (Каскад), совмещающий сильные стороны вероятностного машинного обучения (Факторизационные машины) и детерминированной булевой логики ограничений (аппарат вещественных $R$-функций академика В.Л. Рвачёва).

---

## 🏗️ Компоненты платформы (v2.0.0-pro)

1. **Слой хранения аналитики**: ClickHouse (таблицы логов `watch_logs` и метаданных `users_metadata` / `movies_metadata`).
2. **Слой векторного поиска**: Встроенный Milvus Lite (коллекции `users` и `movies` с нативным индексом `COSINE FLAT`).
3. **Онлайн-инференс**: FastAPI (эндпоинт `/smart-feed` для двухэтапного каскадного ранжирования).
4. **Сквозное обучение и оркестрация**: Пайплайн Dagster + модели dbt + оптимизатор Adam в PyTorch.

---

## 🏎️ Двухэтапный конвейер ранжирования (Smart Feed)

### Этап А: Отбор кандидатов (Candidate Generation) через Milvus Lite
Вместо ресурсоемких операций над реляционными СУБД, отбор ТОП-30 кандидатов по вкусам пользователя перенесен на специализированную векторную базу данных **Milvus Lite**, работающую в embedded-режиме прямо внутри процесса FastAPI.
* **Векторный индекс**: FLAT
* **Метрика расстояния**: `COSINE` (нативное косинусное расстояние между латентными факторами).
* **Механика**: На основе ID пользователя система извлекает его скрытый эмбеддинг из коллекции `users`, после чего выполняет сверхбыстрый поиск ТОП-30 наиболее релевантных фильмов по коллекции `movies`. Метаданные (названия и возрастные цензы) извлекаются из Milvus Lite за один проход вместе с векторами, исключая накладные расходы на сетевые JOIN-запросы.

### Этап Б: Плотное ранжирование (Dense Ranking) и R-Фильтрация
Отобранные 30 кандидатов передаются в вычислительный граф PyTorch, где для каждого фильма параллельно вычисляются две составляющие:
1. **Персональный скор Факторизационной Машины (FM)**: Оценка на основе взаимодействия латентных факторов пользователя и контента с учетом контекста (например, коэффициента удержания `duration_ratio`).
2. **Маржинальность ограничений безопасности ($g_1, g_2$)**: Непрерывные предикаты (например, $g_1 = \text{Возраст пользователя} - \text{Ценз фильма}$).

## 📐 Математика аппарата R-функций Рвачёва

Традиционный подход к жестким ограничениям (Hard Constraints) через дискретные `IF-ELSE` операторы порождает разрывы функций. Такие ступенчатые функции имеют нулевые производные почти везде, что делает их абсолютно непригодными для сквозного обучения нейросетей (Backpropagation).

Теория $R$-функций, разработанная академиком В.Л. Рвачёвым, решает эту проблему. Она позволяет отобразить логические операции булевой алгебры (И, ИЛИ, НЕ) на непрерывные и дифференцируемые алгебраические функции.

В нашей платформе используется каноническая система $R_0$ для реализации **дифференцируемого логического «И» (конъюнкции)**:

$$x \wedge_0 y = x + y - \sqrt{x^2 + y^2}$$

### Интеграция в лосс-функцию PyTorch
Через $R$-конъюнкцию мы связываем вероятностную оценку FM-модели ($f_{\text{FM}}$) и предикаты ограничений контента ($g_1, g_2$):

$$f_{\text{total}} = f_{\text{FM}} \wedge_0 (g_1 \wedge_0 g_2)$$

* **Если правила соблюдены ($g \geq 0$)**: Математика Рвачёва выступает непрерывным «пропускающим вентилем». Финальный скор зависит от интересов пользователя, и модель ранжирует контент на основе FM.
* **Если правила нарушены ($g < 0$)**: Функция $R_0$ бескомпромиссно утягивает итоговый скор глубоко в отрицательный сектор, гарантируя пессимизацию позиции фильма и не допуская его попадания в ТОП-20 выдачи умной ленты.
* **Сквозное обучение (Backpropagation)**: Поскольку функция дифференцируема везде (за исключением точки $0,0$, что обходится добавлением $\epsilon = 10^{-8}$ под корень), градиенты лосса беспрепятственно текут обратно к скрытым факторам FM-модели. Оптимизатор (Adam) учится *заранее* штрафовать скрытые веса за попытку порекомендовать запрещенный контент.

## 🎛️ Офлайн-пайплайн оркестрации (Воркер Dagster + dbt)

Запуск по расписанию через системный `cron` заменен на современную парадигму оркестрации **Dagster** с использованием **Asset-Based (дата-центричного) подхода**. Пайплайн в `offline_train.py` представляет собой прозрачный граф связанных декларативных ассетов (`@asset`):

```text
[ClickHouse: watch_logs] 
       │
       ▼
[dbt модель: stg_watch_features]  <── Расчет предиката g1 на лету в СУБД
       │
       ▼
[PyTorch: trained_embeddings]     <── Обратный проход градиентов через R0
       │
       ▼
[Milvus Lite: Коллекции RAM]      <── Апдейт весов через .upsert()
```


### Роль dbt (Data Build Tool) в ClickHouse
Вся предобработка данных перенесена с Python-слоя на сторону СУБД ClickHouse с использованием принципов **dbt**.
